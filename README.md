# cpp-course-designs · C++ 课程设计合集

> 一句话简介：职工管理系统 + 通讯录管理系统两个 C++ 课程设计工程，多态、继承、文件 IO、STL 的完整实践。

| 项目 | 技术要点 | 文件数 |

## 二、职工管理系统

### 系统定位

公司员工信息管理，四种角色：**老板、经理、普通员工**。不同角色的职责不同，所以要展示的信息也不同——这正是用多态的典型场景。

### 类设计

```
worker（抽象基类）
├── Employee（普通员工）  → 显示「职位：员工」
├── Manager（经理）       → 显示「职位：经理」+ 负责部门
└── Boss（老板）          → 显示「职位：老板」
```

核心在基类的两个纯虚函数：

```cpp
class worker
{
public:
    virtual void showInfo() = 0;          // 显示个人信息
    virtual string getdeptid_name() = 0;  // 部门 id → 职位名称

    int m_id;
    string m_name;
    int m_deptid;
};
```

派生类各自实现这两个接口，于是 `workManager` 里可以用**基类指针数组**统一管理所有人：

```cpp
worker** m_emplyArry;   // 员工数组
int m_EmpNum;           // 记录人数
```

遍历时调用 `showInfo()`，具体调到哪个类的实现由运行时决定——不需要 `if (是老板) ... else if (是经理) ...` 这一串判断。

### 功能

10 个功能模块：

| 功能 | 说明 |
|---|---|
| 增加职工 | 选择角色类型，录入 id/姓名/部门 |
| 显示职工 | 遍历数组调用 `showInfo()` |
| 删除职工 | 按 id 查找，**数组前移 + 人数减一**（不是 `delete` 了事）|
| 修改职工 | 按 id 重新录入 |
| 查找职工 | 按 id 或姓名 |
| 按编号排序 | `sort` 员工数组 |
| 清空文件 | 二次确认后清空数据文件 |
| 退出系统 | 析构中释放堆区数组 |

### 文件持久化

数据存到 `empfile.txt`。`workManager` 构造时读取文件、用 `get_empnum()` 统计人数，再按人数 `new` 出对应大小的指针数组（`init_emp()`）。

```cpp
#define FILENAME "empfile.txt"
```

`file_emp` 成员判断文件是否为空——空文件直接跳过初始化，避免读到垃圾数据。

### 值得留意的两处工程细节

**析构函数释放堆区内存**：

```cpp
~workManager();
```

`m_emplyArry` 是 `new` 出来的指针数组，退出时必须 `delete[]`，每个元素（也是 `new` 出来的）也要单独释放。这是课程设计里最容易被忽略的一步。

**`Isexist(int id)` 返回位置而非布尔值**：

```cpp
int Isexist(int id);   // 存在则返回数组下标
```

删除、修改、查找都复用它——一处实现，三处调用。返回下标同时承担了「存在性判断」和「定位」两个职责，比写三个几乎一样的查找函数干净。

## 三、通讯录管理系统

### 系统定位

通讯录管理，四个功能：**添加联系人、显示联系人、删除联系人、查找联系人**，另有清空和退出。

### 与职工系统的设计差异

这里的对象是同质的（都是「联系人」），没有角色分化，所以**不需要多态**——直接用一个结构体承载：

```cpp
struct person {
    string m_Name;    // 姓名
    int m_Sex;        // 性别：1 男 / 2 女
    int m_Age;        // 年龄
    string m_Phone;   // 联系电话
    string m_Addr;    // 住址
};
```

容器用 `vector<person>` 而不是裸数组。三个直接收益：

- 增删不用管容量，不用手写扩容
- `vector::erase` 删中间元素自动前移，不用自己写搬移循环
- 可以直接用 `find_if` + lambda 做按姓名查找

两个工程放一起看，正好是一组对照：**什么时候该上多态，什么时候一个结构体加 STL 就够了**。

## 五、怎么跑

用 Visual Studio（2019/2022 均可）打开对应 `.sln`，`Ctrl+F5` 直接运行。两个工程都不依赖任何第三方库，纯标准 C++。

改文件名的话注意：`workManager.h` 里 `#include"职工抽象类.h"` 用的是**中文文件名**，且工程默认按系统 ANSI 代码页（GBK）读取。把项目移到非中文系统或改用 UTF-8 编码读取时，需要同步调整源文件编码，否则中文注释和字符串会变乱码。

## 六、这两个工程练到了什么

- **多态与抽象类**：纯虚函数定义接口、基类指针数组统一管理异构对象、虚析构的必要性
- **动态内存管理**：`new`/`delete[]` 配对、指针数组的元素逐个释放、析构函数的职责
- **文件 IO**：二进制文本混用的读写、空文件判断、人数与内存分配的对应关系
- **STL**：`vector` 的增删查、`find_if` + 谓词、`sort` 自定义排序
- **工程组织**：`.h` 只声明不实现、`#pragma once` 防重包含、`.cpp` 分离编译
- **交互细节**：输入容错、二次确认危险操作、菜单循环与状态维护
